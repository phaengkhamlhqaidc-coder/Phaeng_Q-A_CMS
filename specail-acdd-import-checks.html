ACDD Excel import: what actually gets checked

Every validation rule behind the Special Product import screen, column by column — which ones block the Apply button, which columns pass through unexamined, and the three traps that make a file look fine but refuse to import.

How a file travels

Four stages. All of the validation lives in stage 3 — the browser writes no rules of its own, it only paints the answers it gets back.

STAGE 1
Browser uploads
The file is posted as multipart form data. No checks happen here.

Apply writes rows

Apply is disabled while any cell in any row carries an error. There is no partial import — the whole file goes in or none of it does.

The exporting date is stricter than it looks

The date is read as raw text and compared with itself after parsing. Anything that changes shape on the round trip is rejected, which rules out most of what Excel produces naturally.

What the cell must contain

  • ✓ 2026-01-01 text cell
  • ✕ 46023 a real Excel date cell — arrives as a serial number
  • ✕ 2026-1-1 months and days need two digits
  • ✕ 01/01/2026 wrong order and separator
  • ✕ 1 Jan 2026 month names not accepted
  • ✕ 2026-01-01 00:00 no time component allowed

Why a normal Excel date fails

The template marks the column as a date, but the sheet is read with the cell's stored value rather than what Excel displays. Type 1/1/2026 and Excel converts the cell to a date, storing 46023. That number is what reaches validation.

The fix is to make the column text before typing, or to prefix each entry with an apostrophe:

'2026-01-01
'2026-02-01
'2026-03-01

Three traps worth knowing

Each of these produces a file that looks correct on screen but will not import.

Green ticks, Apply still greyed out

The Status column only inspects seven fields: ACDD ID, Product Code, Total Invoice Amount, Destination, TIN, Business ID and two retired bank fields. Errors on the exporting date, currency, unit price, exchange rate or volume never reach it — so every row shows a tick while Apply stays disabled, with nothing on screen explaining why. The error download is the only place the real message appears.

components/Data/DataTable.vue :1810

Volume is mandatory on every row

A blank Volume (KWh) blocks the whole file, even for exports that have nothing to do with electricity. It is also the single most invisible failure on the screen: the volume column shows no error, and the Status tick ignores it. Compounding it, the message reads Invalid unit price, which points at the wrong column.

cms-api · ImportController::importACDDs() :833

A missing header column crashes the upload

Columns are found by their header label on row 2. Delete or rename one and the import fails with a server error instead of a readable message, so keep the downloaded template's header row intact.

cms-api · ImportController::getDataByKey() :69

What no one checks

Border code, product name and business name are all written straight through. A declaration can therefore be saved against a border code that does not exist, or with a business name that contradicts its own Business ID — the import will report success. Anything that must be trustworthy in these three columns has to be verified before the file is uploaded.
